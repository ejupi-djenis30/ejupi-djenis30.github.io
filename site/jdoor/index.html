02 Product tour

Consent at
every step.

The proposed release is designed around an observable support session. These are documented product boundaries, not a live browser simulation.

01

Request.

The person receiving help initiates the session and shares a single-use invitation through a trusted channel.

02

Authorize.

Local approval is required before viewing begins. Control remains separate, optional and revocable.

03

Stop.

Either side can end the session. The host can withdraw control immediately, without creating unattended access.

03 Safety boundary

The boundary is part
of the product.

JDoor Assist is intended only for authorized help on trusted devices. The public documentation makes that constraint legible before any build is distributed.

Static documentation only

The website exposes no commands, agent connection, embedded console or public remote-desktop endpoint.

01

No stealth.

Silent installation, persistence, evasion and covert activation are outside the published product contract.

02

No public control surface.

The tour has no form, iframe or network client. It cannot connect to another device.

03

No unverified distribution.

A public download waits for a tagged source snapshot, dependency review, reproducible checks and integrity information.

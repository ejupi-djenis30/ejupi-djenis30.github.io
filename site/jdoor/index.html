02 Product tour

A support session
that announces itself.

The 1.0.0 contract is designed around an observable session rather than hidden access. These are product boundaries, not a live browser simulation.

01

Request.

A support session starts with a deliberate invitation. The person receiving help can see who is requesting access and what the session is for.

02

Confirm.

Nothing begins before explicit acceptance. Session state and permitted capabilities stay visible while assistance is active.

03

End.

Either side can terminate the session. Verification focuses on bounded behaviour, clear shutdown and an inspectable audit trail.

03 Safety boundary

What this project
does not hide.

JDoor Assist is intended only for devices and people that have explicitly agreed to a support session. The public page keeps that boundary legible before distribution begins.

No live control plane

This website does not expose commands, execute code, contact an agent or provide a public remote-desktop endpoint.

01

No stealth.

Silent installation, persistence, evasion and covert activation are outside the published product contract.

02

No public session.

The tour contains no form, iframe, embedded console or network client. It cannot connect to another device.

03

No unverified build.

Distribution waits for a tagged release, reproducible checks, dependency review and published integrity information.

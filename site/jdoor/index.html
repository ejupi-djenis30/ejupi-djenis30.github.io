01 What the record supports

A desktop application, not a browser promise.

The repository contains launcher, host and viewer flows; pinned TLS pairing; local approval; view-only streaming; revocable input; bounded audit records and automated tests. The website starts no session and exposes no control surface.

SOFTWARE

Working source

Java 21 code, tests, architecture, threat model, privacy notes and packaging scripts.

BOUNDARY

Visible consent

The endpoint is checked by software; the person and every control grant are approved locally.

DISTRIBUTION

Not a download page

No tagged release or signed installer is presented as available. Community builds remain unsigned.

02 Product fit

One visible support moment, on one trusted network.

JDoor makes sense when the person receiving help remains at the computer and can approve, observe and stop the session. Its omissions are part of that product choice.

JDoor fits
  • Home supportA trusted relative helps while the owner remains present.
  • Lab or classroomTwo people share a reachable, trusted local network.
  • Temporary troubleshootingA named helper joins once, compares the code and starts view-only.
Choose something else
  • Internet-wide supportJDoor has no relay, accounts or NAT traversal.
  • Unattended administrationThere is no persistence, background access or fleet control.
  • Content exchangeThere is no file, clipboard, audio or multi-display workflow.

03 Decision record

Each simplification accepts a cost.

These are not universal technology recommendations. They are four boundaries chosen for an authorized, direct-LAN support tool.

Choice Why not the broader alternative Cost accepted

Java 21 + Swing

A browser or Electron shell would still need native screen-capture and input privileges.

Packaging, signing and desktop permissions remain platform-specific.

Direct trusted LAN

A relay and account service would add persistent infrastructure beyond the one-session scope.

No public-internet connection, NAT traversal or centralized discovery.

Ephemeral TLS + exact pin + code

Persistent accounts or device PKI would add enrolment; a token alone would not bind the exact endpoint.

The full link needs a trusted channel, and the host still decides who the person is.

Bounded protocol + view-only start

A general remote-desktop stack brings capabilities outside a visible support session.

No clipboard, files, audio, multi-display or unattended access.

JDoor Assist / Engineering note

The engineering model behind JDoor Assist.

JDoor Assist reframes a collaborative school prototype as consent-based remote support. This note records the intended session model, safety constraints and release threshold; the product itself has a separate home.

01 Session model

Consent at every step.

The intended release is organized around an observable support session. These are documented product requirements, not a live browser simulation.

01

Request

The person receiving help starts the session and shares a single-use invitation through a trusted channel.

02

Authorize

Local approval is required before viewing begins. Control remains separate, optional and revocable.

03

Stop

Either side can end the session. The host can withdraw control immediately, without creating unattended access.

02 Safety boundary

Safety constraints are product requirements.

JDoor Assist is intended only for authorized help on trusted devices. The public record makes that constraint visible before any build is distributed.

Static engineering note
